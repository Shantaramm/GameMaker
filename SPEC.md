## 1. Цель

Веб-сайт, где пользователь:
1. Пишет идею игры (одна фраза или подробный текст).
2. По желанию нажимает «Развернуть в бриф», и ИИ превращает идею в подробный сценарный бриф, который пользователь правит.
3. Нажимает «Создать игру». Бэкенд через GigaChat генерирует игру **как данные** (JSON по строгой схеме), собранные из примитивов движка, строит из них уровни и проверяет проходимость. Графика не генерируется нейросетью: GigaChat только выбирает детали внешности, тайлсеты и предметы из каталога, а рисует движок кодом (раздел 5.8).
4. Играет в браузере: ходит героем по локациям с видом сбоку, говорит с NPC, исследует предметы, открывает сундуки, сражается в пошаговых боях, покупает у торговцев, надевает экипировку, выполняет квесты, приходит к одной из концовок.
5. Получает ссылку на игру, по которой может сыграть кто угодно.

Главный принцип: **LLM не пишет код и не рисует.** LLM заполняет структуру из примитивов и описывает локации смыслом («у колодца», «на втором этаже»), а код строит геометрию, считает баланс и проверяет проходимость. Всё, что можно посчитать кодом, считается кодом, а не моделью.

Жанр не зашит: та же механика должна подходить и для магического фэнтези, и для реалистичного детектива. Поэтому экипировка, предметы и навыки — нейтральные слоты, а их названия и описания придумывает игра (посох и мантия, револьвер и плащ, гаечный ключ и комбинезон).

## 2. Рамки MVP

**Входит:**
- RPG с видом сбоку на 20–40 минут: 5–8 локаций, 1–3 концовки;
- передвижение без прыжков: ходьба влево-вправо, между этажами — лестницы и двери; управление тапом/кликом по точке (герой идёт сам по кратчайшему пути), на компьютере ещё клавиши;
- объекты на карте: NPC с диалогами, торговцы, враги, сундуки, исследуемые предметы (улики, записки, рычаги), переходы между локациями (в том числе запертые);
- пошаговый бой при касании видимого врага: 1–3 врага, действия «Атака / Навык / Предмет / Побег»; случайных встреч нет;
- инвентарь с иконками, экипировка в трёх слотах (в руке, одежда, аксессуар), золото, торговцы (покупка и продажа), опыт и уровни, журнал квестов;
- герой и максимум один компаньон (компаньон следует за героем по карте и говорит в диалогах, в бою не участвует);
- графика кодом: пиксельные портреты с эмоциями (диалоги), спрайты персонажей в полный рост с анимацией ходьбы, тайлсеты локаций, параллакс-фон, существа, иконки предметов (раздел 5.8);
- сохранение прогресса в `localStorage`;
- шеринг по ссылке `/play/{game_id}`.

**Не входит (не делать):** прыжки и платформинг на ловкость, бой в реальном времени, аккаунты и авторизация, оплата, лента игр, сетевая игра, редактор игры, звук, произвольные скрипты в песочнице, перегенерация отдельных блоков, случайные встречи, крафт.

## 3. Стек

- **Бэкенд:** Python 3.11+, FastAPI, Pydantic v2, httpx (async), SQLite (через `sqlite3` или SQLModel), uvicorn.
- **Фронтенд:** Vite + TypeScript, без фреймворка или с Preact. Карта и спрайты — Canvas 2D, интерфейс (диалоги, инвентарь, журнал, бой) — DOM + CSS. Игровые движки не используем.
- **LLM:** GigaChat API (REST через httpx; официальный SDK `gigachat` допустим). Только текст и JSON, генерация изображений GigaChat не используется.
- **Графика:** собственный пиксельный движок на TypeScript + Canvas 2D (раздел 5.8). Библиотека деталей — JSON-файлы в `/pixelart/library`, общие для фронта (рендер) и бэкенда (валидация, каталог для промптов); JSON пишут генераторы `pixelart/tools/*.py`.
- **Общая схема игры:** источник истины — Pydantic-модели на бэкенде. Из них генерируется JSON Schema (`schema/game.schema.json`) и TypeScript-типы для фронта (`npm run gen:types`).

## 5. Движок: примитивы

Игра — документ `Game`. Все ссылки между объектами — по строковым `id` (латиница, `snake_case`). Модели — Pydantic с `extra="forbid"`. Поля, помеченные «код», LLM не заполняет: их выставляют `balance.py` и `levels.py`.

### 5.1 Верхний уровень

```
Game {
  schema_version: "2"
  meta: { title, logline, tone, art_style, language: "ru", est_minutes }
  hero: Character                # role = "hero"
  characters: Character[]        # остальные, включая компаньона
  stats_template                 # код: стартовые статы героя
  progression                    # код: кривая опыта и прирост статов за уровень
  start_skills, start_items, start_equipment: { hand?, body?, trinket? }, start_gold (код)
  skills: Skill[]
  items: Item[]
  enemies: Enemy[]
  shops: Shop[]
  quests: Quest[]
  flags: FlagDef[]
  locations: Location[]
  start_location: location_id
  endings: Ending[]
  levels: { location_id: Level }  # код: геометрия, собранная levels.py (5.6)
}
```

### 5.2 Персонажи

```
Character {
  id, name, role: "hero" | "companion" | "npc" | "antagonist",
  description,                # 2–4 предложения: внешность, характер, мотивация
  appearance: PortraitSpec    # один набор параметров на портрет и спрайт в полный рост (5.8)
}
```

`appearance` задаётся один раз в каркасе и не меняется. Спрайт для карты выводится из той же внешности автоматически (5.8.3) — персонаж одинаков в диалоге и на карте.

### 5.3 Бой, предметы, прогресс

```
Skill { id, name, description, cost_focus, effect: Effect[], target: "enemy" | "self" }

Item {
  id, name, description,
  icon: icon_id,                       # из каталога иконок
  kind: "consumable" | "equipment" | "key" | "misc",
  effect: Effect[],                    # для consumable: что делает при использовании
  equip?: { slot: "hand" | "body" | "trinket",
            bonus: { attack?, defense?, focus?, hp? } },   # для equipment; числа ограничивает balance.py
  value_tier: 1..5,                    # насколько ценен; цену считает код
  price                                # код
}

Enemy {
  id, name, description, tier: 1..5,
  appearance: PortraitSpec | CreatureSpec,
  abilities: EnemyAbility[],           # 0–2
  hp, attack, defense, xp, gold        # код, по tier и положению в игре
}
EnemyAbility { name, effect: Effect[], every_n_turns }

Shop { id, name, items: item_id[], buys: bool }   # buys — покупает ли у героя (за 50% цены)

Quest {
  id, title, giver?: character_id,
  start: Condition,                    # когда квест появляется в журнале
  stages: { text, done: Condition }[]  # этапы; квест выполнен, когда выполнены все
}
```

Состояние квестов не хранится отдельно: оно вычисляется из флагов, предметов и золота. Так квест не может «сломаться» из-за порядка действий.

Опыт и уровни: опыт даётся за победу в бою (`xp` врагов — код). Пороги уровней и прирост статов — `progression` (код). Уровень повышается сразу после боя.

### 5.4 Локации и объекты

LLM описывает локацию **смыслом**: тему, этажи, зоны и что где стоит. Точные координаты ставит сборщик уровней (5.6).

```
Location {
  id, title,
  intro,                       # 1–2 абзаца, показывается при первом входе
  theme: tileset_id,           # тайлсет из каталога (город, дом, таверна, лес, пещера, замок, офис, корабль…)
  background: BackgroundSpec,  # параллакс за уровнем: небо и дальний план из 2а (ground и props игнорируются)
  size: "small" | "medium" | "large",   # ширина этажа: ~2, ~3, ~4 экрана
  floors: 1..3,
  zones: Zone[],               # именованные участки, по порядку слева направо на каждом этаже
  objects: MapObject[],
  on_enter?: Event[]           # сценка при первом входе: narration / dialogue / choice
}

Zone { id, floor: 0..2, name }   # «вход», «стойка трактирщика», «дальний угол»

MapObject = один из (у всех: id, zone, condition? — объект есть на карте, только если условие выполнено):
  Npc      { type: "npc", character: character_id, dialogue: Dialogue, shop?: shop_id }
  Foe      { type: "enemy", enemies: enemy_id[1..3], on_win: Effect[], on_lose: "game_over" | Effect[], can_flee }
  Chest    { type: "chest", look: prop_id, contents: Effect[], requires?: Condition, locked_text? }
  Thing    { type: "thing", look: prop_id, name, event: Dialogue | Choice | Narration, once: bool }
  Exit     { type: "exit", kind: "door" | "left_edge" | "right_edge", to: location_id | ending_id,
             requires?: Condition, locked_text? }
```

- Побеждённый враг и открытый сундук исчезают навсегда. Побег из боя отодвигает героя на шаг назад, враг остаётся.
- `Thing` — всё, что можно осмотреть: улика, записка, рычаг, алтарь. Для детектива это основной инструмент.
- `Exit` с `requires` показывается запертым с текстом `locked_text`.
- Компаньон не объявляется объектом: он следует за героем, если выставлен его флаг (или с начала игры).

### 5.5 События, условия, эффекты

События те же, что в версии 1, но живут внутри объектов (`Npc.dialogue`, `Thing.event`, `Location.on_enter`), а не списком сцены:

```
Dialogue  { type: "dialogue", id, nodes: DialogueNode[], start_node }
Choice    { type: "choice", id, prompt, options: ChoiceOption[] }
Narration { type: "narration", id, text }

DialogueNode   { id, speaker: character_id | "narrator", text, emotion?, choices: DialogueChoice[], next?: node_id | "end" }
DialogueChoice { text, condition?, effects: Effect[], next: node_id | "end" }
ChoiceOption   { text, condition?, effects: Effect[] }
Ending         { id, title, text, kind: "good" | "neutral" | "bad" }
```

Условия и эффекты — структурные объекты, а не строки:

```
Condition = { all: [...] } | { any: [...] } | { not: Condition }
          | { flag: flag_id, is: bool }
          | { has_item: item_id }
          | { stat: "hp"|"attack"|"defense"|"focus", op: ">="|"<=", value }
          | { gold: ">="|"<=", value }
          | { level: ">="|"<=", value }
          | { defeated: object_id }            # враг на карте побеждён

Effect = { set_flag: flag_id, value: bool }
       | { give_item: item_id } | { take_item: item_id }
       | { give_gold: n } | { take_gold: n }
       | { learn_skill: skill_id }
       | { mod_stat: stat, delta }
       | { heal: n } | { damage: n }
       | { goto: location_id | ending_id }    # переход (катсцена, телепорт, финал)
```

Правила рантайма, которые уже определены на этапе 1 (HP не выше максимума, урон вне боя не убивает, `goto` прерывает эффекты и т. д.), сохраняются — они в `NOTES.md`.

### 5.6 Уровни (код, `levels.py`)

Сборщик уровней превращает `Location` в `Level` детерминированно (seed = hash(game_id + location_id)):

```
Level {
  width, height,               # в тайлах (тайл 16×16)
  tiles: string[],             # строки символов: . пусто, # пол/стена, = перекрытие, H лестница, D дверь…
  floors: { y, x0, x1 }[],     # по чему можно ходить
  links: { kind: "stairs" | "ladder", from: [floor, x], to: [floor, x] }[],
  objects: { id, floor, x }[], # куда встали объекты из zones
  spawns: { from: location_id | "start", floor, x }[]
}
```

- Этажи — горизонтальные полосы, связанные лестницами. Зоны делят этаж на участки по порядку, объекты встают в свою зону без наложений.
- Выход `left_edge`/`right_edge` ставится на край этажа, `door` — в зону.
- Проходимость гарантируется построением: все этажи связаны. Валидатор дополнительно проверяет это поиском пути по графу `floors + links`.
- `Level` хранится в игре-JSON. Фронт его только рисует, симулятор ходит по нему же. Одна реализация — нет расхождений между Python и TypeScript.

### 5.7 Рантайм (фронтенд)

- `GameState { location_id, floor, x, hero_stats, level, xp, gold, inventory, equipment, skills, flags, defeated, opened, seen }`.
- **Передвижение:** тап/клик по точке уровня → путь по графу этажей и лестниц → герой идёт с анимацией. Тап по объекту → герой подходит и взаимодействует. На компьютере: A/D или стрелки — идти, W/S у лестницы — подняться или спуститься, E/пробел — взаимодействовать.
- **Камера** следит за героем по горизонтали с параллаксом фона, масштаб целочисленный.
- **Касание врага** запускает бой. Бой как в версии 1: инициатива у героя; урон = `max(1, attack − defense/2) ± 20%`; навык тратит `focus`; побег 50%, если `can_flee`. К статам прибавляются бонусы экипировки и уровня.
- **Варианты с невыполненным условием** показываются серыми с подсказкой («Нужно: ключ от архива»), а не скрываются. Так же — запертые двери и сундуки.
- **Интерфейс:** HUD (HP, фокус, золото, уровень), инвентарь с иконками и экипировкой, окно торговца, журнал квестов, экран боя, диалоговое окно с портретом и эмоцией.
- **Сохранение** в `localStorage` под ключом `game:{id}` после каждого взаимодействия, боя и перехода.

### 5.8 Пиксельный движок

Принцип: **LLM не рисует пиксели, а выбирает готовые детали.** Детали создают генераторы на этапах 2а и 2в, и они проверяются вручную на `/lab`.

#### 5.8.1 Формат деталей и палитр — готово на этапе 2а

Деталь — JSON `{ id, slot, description, w, h, anchor, pixels, variants? }`, символы — слоты палитры (`s/S` кожа, `h/H` волосы, `c/C` одежда, `a/A` акцент…), цвета подставляются при рендере по именам из `palettes.json`. Расширения формата и дополнительные символы описаны в `NOTES.md`.

#### 5.8.2 Портреты, существа, фоны — готово на этапе 2а

- `PortraitSpec` (48×48, 6 эмоций) — диалоги и экран боя с людьми.
- `CreatureSpec` (64×64) — экран боя с монстрами.
- `BackgroundSpec` (160×90) — параллакс-фон локации (небо + дальний план) и фон экрана боя.

#### 5.8.3 Спрайт в полный рост (`walker/`) — этап 2в

- Размер 16×32, вид сбоку, смотрит вправо (влево — зеркально). Кадры: стойка (2), ходьба (4), подъём по лестнице (2).
- Собирается слоями из деталей: тело (кожа), ноги и торс (одежда), волосы, головной убор. **Деталь выбирается по той же `PortraitSpec`**: у каждой детали портрета в библиотеке указан парный id спрайта (`walker: …`), цвета берутся те же. LLM ничего дополнительно не выбирает.
- Минимальная библиотека: парные детали для всех 14 причёсок, 12 нарядов и головных уборов из аксессуаров.

#### 5.8.4 Существа на карте — этап 2в

У каждого тела существа есть вариант для карты 32×32 с двумя кадрами стойки. Люди-враги ходят спрайтами из 5.8.3.

#### 5.8.5 Тайлсеты (`tiles/`) — этап 2в

Тайл 16×16. Тайлсет — набор тайлов одной темы: пол, стена-фон, перекрытие между этажами, лестница, дверь (закрыта/открыта/заперта), окно, 4–6 декораций. Цвета — из настроенческой палитры, как у фонов (время суток тонирует).

Минимальная библиотека: 8 тайлсетов — `town_street`, `house_interior`, `tavern`, `forest`, `cave`, `castle`, `office`, `ship`.

Предметы фона из 2а (`prop`) используются как внешний вид сундуков и исследуемых предметов на карте (`look`).

#### 5.8.6 Иконки предметов (`icons/`) — этап 2в

16×16, цвета — из палитры одежды по `value_tier` (код). Минимум 40 иконок, нейтральных к жанру: оружие разных эпох, одежда, кольца и амулеты, зелья и лекарства, еда, ключи, документы и письма, инструменты, монеты, кристаллы.

#### 5.8.7 Каталог для LLM

`backend/scripts/build_catalog.py` пишет `pixelart/catalog.md`: для каждого слота список `id — описание`, тайлсеты, иконки, имена палитр. Каталог подставляется в промпты, LLM выбирает только из него. Валидатор отклоняет несуществующие id и цвета (ошибка со списком допустимых), после неудачной автопочинки подставляется деталь по умолчанию с предупреждением.

#### 5.8.8 PixelLab (`/lab`, для разработки)

Вкладки: портрет, существо, фон (готово), спрайт в полный рост с анимацией ходьбы для любой внешности, тайлсет, уровень игры (просмотр собранного `Level` целиком), иконки. Загрузка игры по id — на этапе 5. В навигации не показывается.

## 6. Пайплайн генерации

Генерация идёт **по шагам**, а не одним гигантским запросом.

### 6.1 Шаг 0 — бриф (по кнопке «Развернуть»)
Вход: идея пользователя. Выход: markdown-бриф по шаблону (жанр и тон, герой, мир, антагонист, 5–8 локаций с их ролью в сюжете, основной квест и 1–3 побочных, варианты финала) плюс 2–3 уточняющих вопроса. Свободный текст, пользователь правит его в textarea.

### 6.2 Шаг 1 — каркас
Вход: бриф и `catalog.md`. Выход JSON: `meta`, `hero`, `characters` (с `appearance`), `flags`, `quests`, список локаций (`id`, `title`, `theme`, `background`, `size`, `floors`, `zones`, краткое содержание, связи между локациями), `endings`. Без диалогов и объектов. Внешность всех персонажей выбирается здесь за один запрос, чтобы они были визуально разными.

### 6.3 Шаг 2 — локации
Для каждой локации отдельный запрос: вход — каркас, бриф, каталог; выход — `objects` и `on_enter` с диалогами (с `emotion`), сундуками, врагами (`id`, имя, описание, `tier`, способности, `appearance` — без чисел), исследуемыми предметами и выходами.

### 6.4 Шаг 3 — предметы, навыки, торговцы
Отдельный запрос по всем упомянутым id предметов, навыков и магазинов: названия под жанр, описания, `icon`, `kind`, `equip.slot`, `value_tier`.

### 6.5 Шаг 4 — баланс (код, без LLM)
`balance.py`: статы героя и врагов (по `tier` и порядку локаций в графе), опыт врагов и кривая уровней, золото врагов и стартовое, цены предметов по `value_tier`, ограничение бонусов экипировки. Формулы — константы в одном месте.

### 6.6 Шаг 5 — уровни (код, без LLM)
`levels.py` собирает `Level` для каждой локации (5.6).

### 6.7 Шаг 6 — проверка и автопочинка
`validator.py` → список ошибок с путём (`locations[3].objects[2].dialogue.nodes[4].next: unknown node 'n9'`). Если есть ошибки — в GigaChat уходит только проблемный фрагмент + ошибки + схема, ответ — исправленный фрагмент. Максимум 3 итерации, затем статус `failed` с понятной ошибкой для пользователя.

### 6.8 Шаг 7 — плейтест
`simulator.py` (7.2). Непроходимый бой → `balance.py` ослабляет врагов и повторяет. Недостижимая концовка или тупик → назад в шаг 6 с этой ошибкой.

### 6.9 Прогресс
Фоновая задача. Статусы: `queued → outline → locations (k/n) → items → balance → levels → validate → playtest → ready | failed`. Фронт опрашивает `GET /api/games/{id}/status` каждые 2 секунды.

## 7. Проверки

### 7.1 Валидатор (обязателен)
- JSON соответствует схеме (Pydantic).
- Все id уникальны в своём пространстве; все ссылки разрешаются (персонажи, предметы, навыки, враги, магазины, локации, концовки, зоны, детали графики, иконки, тайлсеты).
- Диалоги: `start_node` существует, все `next` существуют, нет узлов-сирот, из каждого узла достижим `end`, у каждого выбора есть вариант без условия.
- Граф локаций: из `start_location` по выходам достижимы все локации и хотя бы одна концовка; у каждой локации есть выход (или `goto` в диалоге).
- Уровни: все объекты стоят на этажах, все этажи связаны, все объекты достижимы от каждой точки появления.
- Экипировка: у `equipment` есть `equip`, бонусы в пределах, заданных `balance.py`; у торговцев есть товары.
- Квесты: условия ссылаются на объявленные флаги, предметы и объекты.
- Флаги объявлены; внешность и графика — из библиотеки; у главных героев не совпадают одновременно причёска, цвет волос и наряд.
- Размеры: 5–8 локаций, ≤ 3 этажа, ≤ 12 персонажей, ≤ 15 объектов на локацию, ≤ 40 узлов в диалоге, реплика ≤ 400 символов.

### 7.2 Headless-плейтест (обязателен)
- Бот-исследователь проходит игру 50 раз (сид фиксирован). В локации он в случайном порядке обходит доступные объекты: говорит с NPC (случайные выборы), открывает доступные сундуки, осматривает предметы, вступает в бои, покупает лечение и лучшую экипировку, если хватает золота, надевает лучшее; затем уходит через случайный доступный выход.
- Бот в бою: атака, навык при наличии фокуса, лечится при HP < 30%.
- Метрики: доля прохождений до концовки, достигнутые концовки, доля побед в каждом бою, средний уровень героя к финалу, число выполненных квестов.
- Требования: каждый бой выигрывается в ≥ 70% встреч; хотя бы одна концовка достигается; нет тупиков (например, ключ за дверью, которую он открывает) и зацикливаний (лимит шагов 5000); основной квест выполним.
- Отчёт сохраняется вместе с игрой (`playtest_report`).

## 8. GigaChat-клиент

- Авторизация: `POST https://ngw.devices.sberbank.ru:9443/api/v2/oauth`, заголовки `Authorization: Basic {GIGACHAT_AUTH_KEY}`, `RqUID: {uuid4}`, `Content-Type: application/x-www-form-urlencoded`, тело `scope={GIGACHAT_SCOPE}`. Токен живёт 30 минут — кэшировать и обновлять заранее (за 60 секунд до `expires_at`).
- Базовый URL API: `https://api.giga.chat` (старый `gigachat.devices.sberbank.ru` выводится из эксплуатации). Вынести в env.
- Чат: `POST /v1/chat/completions`. Модель — из env. По умолчанию: `GIGACHAT_MODEL_TEXT=GigaChat-2-Max` для брифа, каркаса и локаций, `GIGACHAT_MODEL_FAST=GigaChat-2` для автопочинки и предметов. Перед началом работы вызвать `GET /v1/models` и записать реальный список в NOTES.md.
- Генерацию изображений GigaChat не использовать (в запросах не передавать `function_call`).
- TLS: сертификат НУЦ Минцифры, путь — env `GIGACHAT_CA_BUNDLE`, передавать в `httpx(verify=...)`. Отключать проверку сертификата нельзя.
- Ретраи: 3 попытки с экспоненциальной задержкой на 429/5xx/таймаут. Таймаут чата 120 с.
- Логировать каждый запрос (шаг, модель, длительность, токены из `usage`) в `data/logs/{game_id}.jsonl`, без ключа и токена.

### 8.1 Надёжное получение JSON
`json_utils.py`: вырезать первый сбалансированный JSON-объект → `json.loads` (при ошибке — один запрос на починку) → Pydantic; её ошибки уходят в автопочинку (6.7). В промптах всегда: схема фрагмента, один короткий пример, «ответ — только JSON, без пояснений».

## 9. Промпты

`backend/app/generation/prompts/*.md`, плейсхолдеры `{{brief}}`, `{{outline}}`, `{{schema}}`, `{{catalog}}`.
- **brief.md**: роль — сценарист нарративных RPG; шаблон брифа; только оригинальные миры и персонажи.
- **outline.md**: роль — геймдизайнер и художник; лимиты (5–8 локаций, 1–3 концовки, минимум 2 боя, минимум 1 значимый выбор через флаг, основной квест, минимум 1 торговец); связи локаций образуют связный граф; внешность, тайлсеты, фоны — только из `{{catalog}}` и соответствуют описаниям.
- **location.md**: живые короткие реплики со своим голосом у каждого персонажа и `emotion`; 1–2 выбора с последствиями; объекты распределены по зонам; запертые двери и сундуки имеют ключ или условие, достижимые раньше; враги — только `tier` и внешность.
- **items.md**: названия и описания под жанр и тон игры (фэнтези — «посох», детектив — «револьвер»), `icon` из каталога, `value_tier` по ценности.
- **fix.md**: «Вот фрагмент, ошибки и схема — верни исправленный фрагмент целиком».

## 11. Фронтенд

1. **Главная.** Заголовок и строка о продукте. Поле «Опиши свою историю». Кнопки «Развернуть в бриф» и «Создать игру». 3 кликабельных примера идей (фэнтези, детектив, sci-fi).
2. **Бриф.** Textarea с брифом, уточняющие вопросы, кнопка «Создать игру».
3. **Генерация.** Шаги со статусами и ориентир по времени. Как только готов каркас — показать героев: портреты и спрайты, идущие на месте.
4. **Игра.** Уровень с видом сбоку и параллакс-фоном на весь экран; HUD сверху; диалоги в стиле Disco Elysium (ниже); экран боя; выезжающие панели инвентаря, журнала и торговца; экран концовки с кнопкой «Поделиться». Шрифт — пиксельный с кириллицей.
   **Диалоги как в Disco Elysium:** разговор идёт лентой — реплики накапливаются и прокручиваются, а не сменяют друг друга. У каждой реплики имя говорящего; сверху ленты крупный портрет того, кто говорит сейчас, с эмоцией текущей реплики. Варианты ответа — пронумерованный список под последней репликой (на компьютере выбираются ещё и цифрами); недоступные — серые, с условием в квадратных скобках («[Нужно: ключ от архива]»). Выбранный вариант остаётся в ленте как реплика героя. На компьютере лента — колонка справа поверх уровня, на телефоне — нижняя панель на ~60% высоты экрана. Осмотр предметов (`Thing`) и сценки при входе (`on_enter`) идут в ту же ленту голосом рассказчика.
5. Адаптивность: должна нормально работать на телефоне (ширина 375px, портретная ориентация) — это будущий Telegram Mini App.
