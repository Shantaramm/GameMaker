## Состояние проекта

`SPEC.md` — источник истины по требованиям. Работа идёт по этапам из `SPEC.md` §12 строго по порядку. Следующий этап не начинается, пока не выполнен критерий приёмки текущего. Спецификация переписана в версию 2: игра — RPG с видом сбоку (ходьба без прыжков, тап-навигация, локации с этажами, торговцы, экипировка, опыт, квесты, пошаговые бои при касании врага). Порядок этапов: 1 → 2а → 1б → 2в → 2б → 3…6. Готовы 1, 2а и 1б (схема v2, `levels.py`, бот-исследователь, демо-игра v2 на 5 локаций). Следующий — 2в: графика карты (спрайты в полный рост, тайлсеты, иконки). Отклонения от спецификации, правила, которых в ней нет, реальные id моделей GigaChat и типичные ошибки генерации записываются в `NOTES.md` (§15). Прочитай его перед изменением движка или рантайма.

```bash
# бэкенд (из /backend; venv: python -m venv .venv && .venv/bin/pip install -e '.[dev]')
.venv/bin/python -m pytest                                       # все тесты
.venv/bin/python -m pytest tests/test_broken_games.py -k orphan  # один тест

.venv/bin/python scripts/build_catalog.py   # pixelart/library → pixelart/catalog.md (проверяет test_catalog_is_in_sync)

# библиотека деталей (из корня; нужен Pillow — он есть в backend/.venv)
backend/.venv/bin/python pixelart/tools/gen_library.py            # генераторы → pixelart/library/*.json
backend/.venv/bin/python pixelart/tools/preview.py out.png hair   # быстрый лист превью: random|emotions|hair|head|outfit|accessory|facial_hair|creatures|backgrounds|props

# фронтенд (из /frontend)
npm run dev          # http://localhost:5173/lab — PixelLab
npm run typecheck
npm run gen:types    # schema/game.schema.json → src/types/game.ts (после export_schema)
npm run screens      # скриншоты в docs/lab/; падает при ошибках/предупреждениях в консоли
```

После правки генератора деталей: `gen_library.py` → `build_catalog.py` → `pytest` (тесты `test_art.py` ловят «дырки» и съехавшие слои) → `npm run screens` и посмотреть глазами.

Будущие (из спецификации; проверить, когда появятся файлы):

```bash
uvicorn app.main:app --reload            # API
python -m app.gigachat.client --smoke    # токен → список моделей → короткий чат (этап 3)
```

Конфигурация лежит в `.env` (шаблон `.env.example`, §13). Для GigaChat нужен корневой сертификат НУЦ Минцифры (`GIGACHAT_CA_BUNDLE`). Отключать проверку TLS нельзя.

## Архитектура

**Главный принцип: LLM не пишет код и не рисует пиксели.** GigaChat заполняет документ `Game` (JSON) из примитивов движка и выбирает детали графики по id из каталога. Всё, что можно посчитать, считает код: статы врагов (`balance.py`), проверку ссылок и достижимости (`validator.py`), проходимость (`simulator.py`).

**Схема — единый контракт для трёх частей системы.** Pydantic-модели в `backend/app/engine/schema.py` (`extra="forbid"`) — источник истины. Из них генерируется `schema/game.schema.json`, из неё — TS-типы для фронта. Меняя модель, синхронно обновляй JSON Schema, TS-типы, промпты (`{{schema}}`), валидатор и `tests/fixtures/demo_game.json`.

**Условия и эффекты — структурные объекты, а не строки-выражения** (§5.5). Они исполняются в двух местах: в TS-рантайме (`frontend/src/engine/conditions.ts`, `battle.ts`) и в Python-симуляторе. Семантика должна совпадать, в том числе формула урона `max(1, attack − defense/2) ± 20%` и побег с вероятностью 50%.

**Мир описывается смыслом, геометрию строит код.** LLM задаёт локацию темой, этажами, зонами и объектами в зонах; `backend/app/engine/levels.py` детерминированно собирает из этого `Level` (тайлы, этажи, лестницы, координаты объектов) и сохраняет его внутри игры-JSON. Фронт уровень только рисует, симулятор ходит по тому же `Level` — второй реализации сборщика на TypeScript быть не должно.

**Пайплайн генерации** (`backend/app/generation/pipeline.py`) идёт по шагам, а не одним запросом: бриф (свободный markdown) → каркас (персонажи с внешностью, квесты, список локаций) → по одному запросу на локацию → предметы и магазины → баланс (код) → уровни (код) → валидатор и автопочинка (не более 3 итераций, в LLM отправляется только сломанный фрагмент) → headless-плейтест (бот-исследователь, 50 прогонов с фиксированным сидом). Работает как фоновая задача, статусы опрашиваются через `GET /api/games/{id}/status`. Ответ LLM всегда проходит через `json_utils.py`: вырезать сбалансированный JSON → `json.loads` → один запрос на починку → Pydantic.

**Пиксельный движок** (`frontend/src/pixel/`, Canvas 2D). Детали в `/pixelart/library/*.json` — это строки символов, где символ означает **слот палитры**, а не цвет. Конкретные цвета подставляются при рендере по именам из `palettes.json`. JSON не правят руками: его пишут генераторы `pixelart/tools/*.py`. Библиотека общая для трёх потребителей: фронт по ней рисует (бандлится через `import.meta.glob`), бэкенд по ней валидирует (`backend/app/engine/art.py`, вызывается из `validate()` по умолчанию), `catalog.md` уходит в промпты. Каждая деталь ставится своим `anchor` в общую точку привязки слоя из `layout.json`, поэтому слои не съезжают. Расширения формата (`back`, `clip`, `points`, `attach`, `setting`) и дополнительные символы палитры описаны в `NOTES.md`. Рендер детерминирован: портрет кэшируется по ключу `(character_id, emotion)`, процедурные слои фона используют `seed = hash(game_id + scene_id)`. Если деталь неизвестна и автопочинка не помогла, подставляется дефолт того же слота с предупреждением, игра не падает.

**Инварианты валидатора, на которые опирается рантайм:** все ссылки и флаги объявлены; все локации достижимы по выходам, все объекты — по этажам и лестницам; из каждого узла диалога достижим `end`; из `start_location` достижима хотя бы одна концовка; нет запертых дверей с ключом за ними; каждый бой выигрывается не менее чем в 70% симуляций. Рантайм не обрабатывает нарушения этих правил, потому что они туда не должны попасть.

## Ограничения MVP

В MVP не делать: прыжки и платформинг, бой в реальном времени, случайные встречи, авторизацию, оплату, звук, анимацию спрайтов, редактор игр, генерацию изображений через GigaChat (не передавать `function_call`). Интерфейс на русском, верстка должна работать при ширине 375px (будущий Telegram Mini App). Страница `/lab` (PixelLab) нужна только разработчикам и в навигации не показывается.
